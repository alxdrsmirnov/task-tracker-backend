# Discovery 04: Классификация субдоменов

> Финальный шаг стратегического цикла: классификация кандидатов тестом дифференциации и перекрёстная проверка результата.

## Тест

Из вопроса «за что компания готова платить» (discovery 01):

- **Core** — за это платят, этим продукт отличается от простых трекеров; ошибка модели = смерть продукта.
- **Supporting** — специфично для домена, но заменяемо без потери отличия; ошибка = баг.
- **Generic** — стандарт рынка, покупное решение.

## Результат

| Субдомен | Обоснование тестом | Класс |
| --- | --- | --- |
| Исполнение работы (Work Execution) | «Одна работа — много проектов, один ответственный, видимое состояние» — главная ценность | **Core** |
| Организация работы (Work Organization) | «Каждый отдел настраивает свой процесс» — второй дифференциатор | **Core** |
| Структура компании (Workspace) | Нужно для B2B, не отличает продукт; заменяемо стандартной org-моделью | Supporting |
| Уведомления (Notification) | Специфичная группировка Inbox, но заменяемо готовым notification-center | Supporting |
| Установление личности (Identity) | Полностью покупное (Auth0/Keycloak) | Generic |
| Определение доступа | Не субдомен — политики внутри владельцев (discovery 03) | — |

## Перекрёстная проверка

Два независимых пути привели к одной карте:

1. **Сверху вниз (из деятельности):** домен → боль/ценность → возможности → слипание → тест (discovery 01–04).
2. **Снизу вверх (из критики модели):** разбор перегруженного Work Coordination, исследование реальной Asana, разбор hotspots → `docs/domain-model.md`.

Совпадение: два core (Work Execution, Work Organization), два supporting (Workspace, Notification), один generic (Identity); доступ — политики внутри контекстов; Collaboration — внутри Work Execution до триггера.

## Что зафиксировано
