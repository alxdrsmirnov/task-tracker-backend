# Focus

## Purpose

Force focused, deliberate reasoning before producing any answer or code. No rushing, no unchecked assumptions.

## Hard Stop

**It is FORBIDDEN to write code or give a final answer before doing the reasoning steps below.**

If the task is trivial (typo, rename, obvious question) — a short analysis block is still required. In all other cases — full block.

## Non-Negotiable Rules

1. **Think in text, not in your head.** Every non-trivial decision MUST be written out. Phrases like "I thought about it and decided" do NOT count.
2. **No code before analysis.** Code is not generated until the context is mapped and assumptions are verified.
3. **Verify, don't guess.** Before any claim about the codebase (file names, existing logic, conventions), confirm via Grep / Read. Do not invent patterns that do not exist in the project.
4. **Mark assumptions explicitly.** Every "I assume that…" must be flagged and, where possible, verified against the code.

## Forbidden

- Starting the response with code before the analysis block.
- Vague phrases like "handle errors", "consider edge cases" without naming specific errors or cases.
- Skipping the self-check section.
- Pseudo-analysis: filling sections formally with no substantive thought.

When in doubt — go deeper, not shallower.
