# Git-Коммит

## Рабочий Процесс

1. Проанализируй состояние репозитория:
   - `git status`
   - `git status -s`
   - `git diff --stat`
   - `git diff --name-status`
   - `git log --oneline -5`
2. Проверь staged и unstaged изменения и не включай секреты или неожиданные файлы.
3. Сгенерируй 7–10 вариантов сообщения в формате `{type}({scope}): {Описание на русском в прошедшем времени}`.
4. Попроси пользователя выбрать ровно один вариант.
5. Если доступен инструмент выбора, используй один single-choice вопрос; иначе покажи обычный нумерованный список и жди номер.
6. Считай выбор пользователя подтверждением только на `git commit`.
7. Выполни `git add .`.
8. Выполни `git commit` с выбранным сообщением.
9. Покажи хэш, статистику коммита и состояние ветки.

## Формат Сообщения

```text
{type}({scope}): {Описание на русском}
```

Начинай описание после `:` с заглавной буквы и используй завершённое действие: `Добавил`, `Исправил`, `Вынес`, `Обновил`, `Упростил`, `Удалил`.

## Типы

- `feat` — новая функциональность.
- `fix` — исправление ошибки.
- `refactor` — изменение структуры без нового поведения.
- `chore` — dependencies, config, scripts и project tooling.
- `docs` — документация.
- `test` — тесты.

## Scope

Выбирай ближайший осмысленный scope: `auth`, `user`, `workspace`, `task`, `http`, `ws`, `common`, `infra`, `domain`, `app`, `deps`, `config`, `docs`, `test`.

Если точного scope нет, используй имя ближайшего изменённого feature или module.

## Правила

1. Всегда выполняй `git add .` только после выбора сообщения.
2. Не выполняй push.
3. Не создавай MR/PR.
4. Не коммить секреты и `.env` без явной просьбы.
5. Если коммитить нечего, сообщи об этом и остановись.
6. Не выбирай сообщение за пользователя.
7. Если пользователь отклонил варианты, сгенерируй новый список.

## Примеры

| Изменения | Сообщение |
| --- | --- |
| Регистрация пользователя | `feat(auth): Добавил регистрацию пользователя` |
| Проверка участника workspace | `fix(workspace): Исправил проверку доступа участника` |
| Перенос Prisma | `refactor(infra): Вынес Prisma в отдельный слой` |
| Обновление NestJS | `chore(deps): Обновил NestJS и связанные пакеты` |
| Тесты задач | `test(task): Добавил сценарии изменения статуса задачи` |

## Формат Ответа

Перед коммитом:

```text
Изменённые файлы:
{список из git status -s и git diff --stat: путь, статус, +N/-M строк}

Выбери название коммита:
1. {message_1}
2. {message_2}
3. {message_3}
```

После коммита:

```text
✓ Коммит: {message}
✓ Хэш: {hash}

Файлы:
{вывод git show --stat HEAD}
```
